### CONSTRAINTS
- Do NOT include a "summaryTable" field — it does not exist in the schema and
  will fail validation. Any summary view is derived from "days" elsewhere.
- Omit a field only when the schema marks it optional; every other field is required.
- "reps" is always a string, even for a single number, so it can express a
  range, e.g. "10-12" or "8".
- "restSeconds" on an exercise is a single integer (seconds). "phaseInfo.restSeconds"
  is a different field: a string range, e.g. "60-90". Do not confuse the two shapes.
- "program.lastUpdated" is a string in "YYYY-MM-DD" format.
- "program.gymId" accepts either a legacy integer (1 and up) or a 32-character
  lowercase hex club GUID — never a club name or address.
- "extraEquipment[].kind" is always the literal string "gear" when present.
- "equipmentId" on an exercise is optional: omit it (or leave it empty) for
  bodyweight work, and the app shows the exercise name only in that case.
- If field 8 (prior progress export) names an exercise you are repeating this phase,
  reuse its exact name and spelling. Progress and prefilled weights are tracked by
  exercise name, so a respelled exercise starts a new, empty history.
- "videoQuery" (optional) is a search query for THIS exercise on THIS equipment, not a
  generic machine query — set it only to override the app's automatic query.
- Write every text field in ONLY the language given in REQUEST field 7 — one
  plain string per field (e.g. "label": "Monday"), never a multilingual
  object (NOT "label": {"en": "Monday", "es": "Lunes"}). The app displays
  routine text exactly as written and does not translate it, so do not try
  to match any other language, including the app's own interface language.
