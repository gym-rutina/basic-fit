# Стварэнне Руціны з дапамогай LLM

Гэта кіраўніцтва ператварае праграму трэніровак, якая існуе толькі ў вашай галаве
(ці ў нататках трэнера), у файл `rutina.json`. Запоўніце prompt у верхняй частцы гэтага
экрана, скапіруйце яго ў **любы** LLM-чат (ChatGPT, Claude, Gemini — усё, што ёсць пад
рукой), і імпартуйце адказ у прыклад **Rutina**.

Веданне JSON не патрабуецца. Без уліковага запісу, без ключа API — гэта працуе ў
звычайным акне чата браузера.

> **Мова.** Поле 7 задае мову тэксту руціны — пішыце яе на любой мове, якую
> можа вырабіць LLM (не толькі англійскай/іспанскай/беларускай). Rutina
> паказвае назвы практыкаванняў, меткі дзён, тэхнічныя падказкі, правілы і
> нататкі **дакладна так, як іх напісаў LLM**, на адной мове, і ніколі іх не
> перакладае, не пераназывае і не патрабуе адпаведнасці мове інтэрфейсу
> праграмы (яна настройваецца асобна, у **Наладах**). Просіце LLM пра **адзін
> просты радок тэксту на поле** — ніколі шматмоўны аб'ект накшталт
> `{"en": "Monday", "es": "Lunes"}`.

Усе даведачныя даныя знаходзяцца ў публічным рэпазіторыі
[github.com/bthos/gym-routine-basic-fit](https://github.com/bthos/gym-routine-basic-fit).
Prompt паказвае LLM, дзе іх чытаць — вам **не** трэба самастойна капіраваць схему ці
файлы абсталявання.

| Даныя | URL |
|-------|-----|
| Схема (крыніца ісціны) | [rutina.schema.json](https://cdn.jsdelivr.net/gh/bthos/gym-routine-basic-fit@main/data/schema/rutina.schema.json) |
| Каталог абсталявання | [equipment.json](https://cdn.jsdelivr.net/gh/bthos/gym-routine-basic-fit@main/data/equipment.json) |
| Спіс залаў (для LLM) | [gyms.json](https://cdn.jsdelivr.net/gh/bthos/gym-routine-basic-fit@main/data/gyms.json) |
| Даведачны прыклад | [phase1-monday.json](https://cdn.jsdelivr.net/gh/bthos/gym-routine-basic-fit@main/data/examples/phase1-monday.json) |

> **LLM без доступу да інтэрнэту?** Націсніце кнопку **Спампаваць** на гэтым экране
> кіраўніцтва, каб захаваць zip-архіў з усімі чатырма файламі даных непасрэдна на
> прыладу — адзін файл, гатовы для далучэння да чата, а не толькі прагляд у браузеры.
> Хочаце атрымаць іх самастойна? Табліца вышэй спасылаецца непасрэдна на зыходныя
> файлы ў рэпазіторыі.

## Крок 1 — Скапіруйце prompt

Скарыстайцеся кнопкай **Скапіраваць** над гэтым кіраўніцтвам. Prompt пачынаецца з
**REQUEST** — запоўніце кожны нумараваны радок (звычайны тэкст, без JSON) перад адпраўкай.

> **Поле 6 — мэтавы зал**
> Знайдзіце назву і лічбавы **id** вашага зала ў **[спісе залаў →](https://bthos.github.io/gym-routine-basic-fit/gyms.html)**
> (адкрываецца ў новай укладцы). Таксама на ўкладцы **Catálogo** у прыкладзе Rutina.

| # | Поле | Прыклад | Абавязковае |
|---|------|---------|-------------|
| 1 | Для каго гэта / назва праграмы | "Іван — Фаза 2" | так |
| 2 | Асноўная мэта ў гэтай фазе | "Гіпертрафія, больш аб'ёму" | так |
| 3 | Дзён у тыдзень | 4 | так |
| 4 | Бюджэт часу сесіі | "45-60 хвілін" | так |
| 5 | Траўмы / рухі, якіх трэба пазбягаць | "Пазбягаць ваеннага жыму праз правае плячо" | не — напішыце "няма" калі няма |
| 6 | Мэтавы трэнажорны зал | "Avda. Andalucía, Centro Comercial Alameda (id 3)" | так |
| 7 | Мова для выходнага тэксту | "Беларуская" | так |
| 8 | Экспарт папярэдняга прагрэсу | Markdown з **Historial → Exportar** у Rutina | не — прапусціце для першай фазы |

Уключэнне "output only JSON" і ў пачатку (`ROLE`), і ў канцы (`OUTPUT`) — намерана.

## Крок 2 — Імпарт у прыклад Rutina

1. Скапіруйце адказ JSON ад LLM (без markdown-агародж).
2. Адкрыйце экран **Імпарт** у прыкладзе Rutina і ўстаўце, ці загрузіце файл `.json`.
3. Націсніце **Імпарт**. Прыклад валідуе па той жа схеме і каталогу абсталявання.

Калі валідацыя не прайшла, скапіруйце спіс памылак і ўстаўце назад у LLM-чат.
Папрасіце выправіць і паўторна вывесці поўны JSON. Паўторыце, пакуль імпарт не ўдасціцца.

**Неабавязкова — валідацыя на камп'ютары:**

```bash
npm run validate-rutina -- шлях/да/вашай-rutina.json
```

| Вынік | Прыклад вываду | Што рабіць |
|---|---|---|
| Поспех | `✓ Valid rutina: 4 days, 22 exercises` | Імпарт у прыклад |
| Памылка схемы | `days[1].label: required` | Уставіць увесь блок памылак назад у LLM |
| Памылка ID абсталявання | `days[2].exercises[0].equipmentId "g3-xx" not found` | Тое ж — уставіць дослова |

## Практычны прыклад

**REQUEST запоўнены (верх скапіраванага prompt):**

```text
1. Для каго гэта / назва праграмы: Назва — Фаза 2
2. Асноўная мэта ў гэтай фазе: Гіпертрафія, больш мышечнага аб'ёму
3. Дзён у тыдзень: 4
4. Бюджэт часу сесіі: 45-60 хвілін
5. Траўмы / рухі, якіх трэба пазбягаць: няма
6. Мэтавы трэнажорны зал: Avda. Andalucía, Centro Comercial Alameda (id 3)
7. Мова для выходнага тэксту: Беларуская
8. Экспарт папярэдняга прагрэсу (неабавязкова): (яшчэ няма)
```

**LLM чытае схему і абсталяванне па URL у DATA SOURCES і вяртае JSON.**

**Імпарт** у Rutina, ці `npm run validate-rutina -- data/rutina-nombre-fase2-draft.json`.

## Вырашэнне праблем

- **LLM не можа загрузіць URL.** Націсніце кнопку **Спампаваць** на гэтым экране
  кіраўніцтва, каб захаваць zip-архіў з файламі DATA SOURCES, і прыкладзіце яго да
  чата ўручную — назвы файлаў унутры супадаюць з тымі, што ў prompt. Табліца URL
  вышэй таксама падыходзіць для LLM/браузераў, якія могуць атрымаць файлы самастойна.
- **Чат LLM не можа адкрыць `.zip`-укладанне.** Разархівуйце файл лакальна і
  прыкладзіце ці ўстаўце асобныя файлы — `rutina.schema.json`, `equipment.json`,
  `gyms.json`, `phase1-monday.json`.
- **LLM дадаў уступ ці абгорнуў JSON у markdown.** "Output ONLY the JSON object, no markdown fence, no explanation."
- **Адказ абрываецца сярод JSON.** "continue from where you stopped, still outputting only JSON".
- **ID абсталявання не знайдзены.** LLM павінен выбіраць id з `equipment.json` для вашага зала.
- **Не ведаеце id зала?** [Спіс залаў](https://bthos.github.io/gym-routine-basic-fit/gyms.html) ці ўкладка **Catálogo** у Rutina.

## Выкарыстанне экспарту прагрэсу (поле 8)

Пасля фазы **Гісторыя → Экспарт прагрэсу** ў Rutina стварае Markdown-тэкст, які
можна ўставіць у поле 8 як ёсць:

```
Prensa de Pecho (g3-s10)
  · 32kg / difícil
  · 32kg / normal
  · 35kg / fácil

Jalón al Pecho (g3-s30)
  · 45kg / normal
  · 48kg / fácil

Sesiones sin completar:
  · Lunes — 2026-07-01 (abandonada)
```

LLM бачыць па гэтым, якія вагі падыходзілі, што было занадта лёгка ці цяжка, і якія
сесіі былі пакінуты — і карэктуе наступную фазу адпаведна.

**Поўны фармат:** [`docs/export-format.md`](export-format.md)

## Захаванне ідэнтыфікацыі практыкаванняў паміж фазамі

Прагрэс, прапанаваная вага і спасылкі на відэа-ўрокі адсочваюцца **па практыкаванні**, а
не па трэнажоры — два розныя практыкаванні на адным трэнажоры (напрыклад, жым лежачы і
жым пляча на адной шматпазіцыйнай машыне) адсочваюцца, будуюцца ў графікі і экспартуюцца
незалежна. Практыкаванне вызначаецца па **назве** разам з абсталяваннем, таму пры
напісанні REQUEST наступнай фазы:

- **Паўтарайце дакладную назву з папярэдняй фазы**, калі новая фаза паўтарае тое ж
  практыкаванне. Экспарт прагрэсу (поле 8) друкуе назву кожнага практыкавання дакладна
  так, як яна была запісана — скапіруйце яе дакладна, а не перафармулюйце. Змененая назва
  лічыцца *іншым* практыкаваннем з пустой гісторыяй — вы страціце назапашаныя тэндэнцыю
  вагі і прапанаваную вагу.
- **`videoQuery` — гэта пошукавы запыт для *гэтага практыкавання на гэтым абсталяванні*,
  а не для трэнажора наогул.** Праграма ўжо аўтаматычна складае добры запыт з назвы
  практыкавання і назвы абсталявання — задавайце `videoQuery` толькі каб яго
  перавызначыць.
