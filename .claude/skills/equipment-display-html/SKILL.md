# Equipment Display HTML — Catalog Conventions (skill)

Project-specific rules for rendering BasicFit / Matrix / ZIVA equipment. Adapted from the Cursor rule `html-equipment-display.mdc`. **The standalone `equipment-catalog.html` viewer and its generator (`scripts/build-catalog.js`) were deleted** in the 2026-08-09 gym-directory-and-catalog feature (R8.8) — the equipment catalog now lives only in the PWA's **Catálogo** tab. Load this skill when touching either of the two surfaces that remain:

1. **The PWA** — `app/src/screens/CatalogScreen.jsx`, which renders `design-system/components/composite/EquipmentCard.jsx` (React, props-driven — see below).
2. **Legacy static pages** — `rutina_*.html`, generated by `scripts/build-rutina.js` (vanilla JS, `fetch` + `innerHTML` — see below).

The **source of truth is `data/equipment.json`** (validated against `data/schema/equipment.schema.json` and `npm run validate-data`) — never hardcode equipment data into either surface.

## Data integration

The two surfaces get equipment data two different ways — don't cross the pattern from one into the other:

- **PWA (`CatalogScreen.jsx`):** equipment is imported as a JS module at build time — `import equipmentData from '../../../data/equipment.json'` (see `app/src/data/equipment.js`) — then passed down as props to `EquipmentCard`. No runtime `fetch`.
- **Legacy static pages (`rutina_*.html`):** `scripts/build-rutina.js` generates pages that `fetch('data/equipment.json')` at page-load and render from the response. This is the surviving use of the old embed-JSON-for-offline pattern; follow it if you touch `build-rutina.js`, don't introduce a live fetch anywhere in the PWA.

```javascript
// ✅ GOOD (rutina_*.html only) — load from data/equipment.json at runtime
fetch('data/equipment.json')
  .then(response => response.json())
  .then(data => renderEquipment(data.equipment));
```

## Equipment card structure

Each card includes, at minimum:

- **Model code** (e.g. `G3-S10`, `ZVO-DBPU-1648`) — prominently displayed, uppercase with hyphens as shipped in `modelCode`.
- **Bilingual names** — Spanish (`names.es`, primary) and English (`names.en`, secondary); Belarusian (`names.be`) where present.
- **Equipment image** — from the Matrix/ZIVA CDN (`images.jhtassets.com`); see the `matrix-image-handling` skill for URL rules.
- **Muscle groups** — both primary and secondary.

Two fields are convention on `rutina_*.html` but **not currently rendered by the PWA's `EquipmentCard.jsx`** — worth knowing before assuming parity between the two surfaces:

- **Instructions** (`instructions.es` / `instructions.en`) — rendered on the legacy pages (see Instructions rendering below); `CatalogScreen.jsx` does not pass `instructions` to `EquipmentCard` at all today.
- **Category badge** — the Category colours table below is followed by the Catálogo tab's **filter pills** (`FilterPill`, one per `category` value), not by a badge on the card itself; `EquipmentCard.jsx` shows a weight badge, not a category-color badge.

If you add either back to the PWA card, update this note rather than leaving it stale again.

## Image handling (rutina_*.html)

Always include a fallback and lazy loading:

```html
<!-- ✅ GOOD — fallback + loading state -->
<img
  src="${equipment.images[0].url}"
  alt="${equipment.names.es}"
  loading="lazy"
  onerror="this.src='placeholder.jpg'"
/>

<!-- ❌ BAD — no fallback -->
<img src="${equipment.images[0].url}" />
```

The PWA's `EquipmentCard.jsx` instead shows a "Sin imagen" placeholder `<span>` when `imageUrl` is falsy (no `onerror` — React re-renders on prop change, not on load failure) — match whichever surface you're editing, don't port one pattern into the other unmodified.

## Instructions rendering (rutina_*.html)

Equipment instructions contain HTML markup — render with `innerHTML`, not `textContent`:

```javascript
// ✅ GOOD — preserves HTML formatting
instructionsDiv.innerHTML = equipment.instructions.es;

// ❌ BAD — strips the formatting
instructionsDiv.textContent = equipment.instructions.es;
```

> Because instructions are injected as HTML, they must come from the trusted `data/equipment.json` only. Do not `innerHTML` untrusted or user-supplied strings. In React, the equivalent is `dangerouslySetInnerHTML` under the same trust rule — use it only for data read from `data/equipment.json`, never for user- or LLM-authored text.

## Language support

- **Primary:** Spanish (`es`) — displayed by default.
- **Secondary:** English (`en`) — offer a toggle/option.
- **Additional:** Belarusian (`be`) — when present in the data. Belarusian content in `data/equipment.json` is always **hand-authored**, never scraped or machine-translated, even when `en`/`es` come from a live product page.

## Category colours

Consistent scheme across the catalog's category filter pills (8 values as of the 2026-08-09 catalog expansion — `free-weights` and `accessories` were added alongside the original 6):

| Category | Colour family |
|----------|---------------|
| Chest | Purple / violet |
| Back | Blue |
| Shoulders | Orange |
| Arms | Red |
| Core | Green |
| Legs | Indigo |
| Free weights | Amber |
| Accessories | Teal |

`kind` (`machine` / `free-weight` / `accessory`, in `data/equipment.json` but not `category`) is a separate axis used to group the PWA's equipment-selection overlay, not the catalog's category filter — the two occasionally disagree on purpose (e.g. `G3-MS24` is `category: "free-weights"` but `kind: "machine"`). Don't conflate them when choosing a color or a grouping.

## Styling guidelines

- Modern CSS — gradients and shadows.
- Responsive, mobile-first.
- Consistent category colours (table above).

## Talaka fit

This is a domain-convention skill, not a pipeline stage. It carries knowledge; it doesn't own a handoff. When `@cmok` builds or edits equipment display code, these rules apply. After changes, the data gate is `npm run validate-data` (per `.tlk/PROJECT.md`); `npm run normalize-equipment` applies standard data fixups (idempotent, writes only on change); the legacy-page build is `npm run build-rutina` (`build-catalog` no longer exists — deleted with `equipment-catalog.html`). Pair with the `matrix-image-handling` skill whenever image URLs are involved.
